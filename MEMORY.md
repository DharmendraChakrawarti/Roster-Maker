## 3. Role-Based Architecture & View Isolation

The platform enforces strict role separation across 3 user tiers:

| Role | Access Scope | Navigation & Pages | Key Capabilities |
|------|--------------|-------------------|------------------|
| **ADMIN** | System-wide Administration | `/admin` (*System Administration*) | User Directory & Account management, Department CRUD, system metrics. Operations section is strictly excluded. |
| **MANAGER** | Private Management Workspace | `/dashboard`, `/employees`, `/shifts`, `/roster` | Private isolated team members, custom shift quotas, capacity calculator, automated fair roster generation, Excel export, manual schedule adjustments. |
| **USER (Staff)** | Staff Schedule Portal | `/roster` (*My Shift Schedule*) | Read-only view of published monthly shift rosters generated by their assigned reporting manager, Excel export. |

## 4. Design System & Mobile Responsiveness

- **Aesthetic**: Hotstar-inspired sleek dark theme (`#0f1014`, `#16171c`, `#1c1d24`) with vibrant accents (`#1a73e8`, `#34a853`, `#f9ab00`, `#ea4335`).
- **Mobile-First Responsiveness**:
  - Base mobile font size set to `1rem` ($16\text{px}$) to prevent browser auto-zooming on focus.
  - Big prominent typography: Page titles `1.65rem` ($900\text{ weight}$), KPI metrics `2.1rem` – `2.2rem`, card headings `1.25rem` – `1.35rem`, form labels `0.88rem` ($800\text{ weight}$).
  - Touch-friendly controls: Buttons and inputs have $\ge 46\text{px}$ – $48\text{px}$ touch targets.
  - Mobile top app bar with role badge, hamburger toggle, and slide-out navigation drawer with backdrop overlay.
  - Sticky employee name column ($165\text{px}$) on mobile calendar matrix with smooth touch scrolling and $36\text{px}\times 28\text{px}$ high-contrast shift tags.

## 5. Algorithmic Scheduling Engine & Features

1. **Multi-Month Historical Lookback & Continuity**:
   - Inspects previous monthly rosters to maintain rotational continuity across month boundaries.
   - Eliminates 6-day fatigue weeks across month seams.
   - Enforces rolling equality for night shifts, weekend shifts, and rest days.
2. **Weekly Rest Days & Fatigue Protection**:
   - Strictly back-to-back consecutive rest days (2 days/week standard or 1 day/week) distributed smoothly via cyclical pattern offsets (`pattern = i % 7`).
   - Night-to-Morning rest rule constraint (staff working Night shift cannot work Morning next day).
3. **Staffing Capacity & Quota Calculator**:
   - Live mathematical balancing of weekly staffing capacity ($N \times 5$ slots/week) vs configured demand ($5 \times \text{weekday} + 2 \times \text{weekend}$).
   - Equilibrium status indicator (`OPTIMAL`, `OVERSTAFFED`, `DEFICIT`) with recommended shift quotas.
4. **Excel Export**:
   - Generates formatted, color-coded `.xlsx` monthly matrix worksheets.

## 6. Database Schema & Flyway Migrations

The H2 file-based database (`./data/smartroster`) uses Flyway migrations:

| Migration | Key Tables & Modifications |
|-----------|---------------------------|
| **V1__initial_schema.sql** | `employees`, `shift_configs`, `rosters`, `roster_assignments` |
| **V2__auth_and_departments.sql** | `users`, `departments`, JWT authentication, role enum (`ADMIN`, `MANAGER`, `USER`), reporting `manager_id` foreign key |
| **V3__multi_manager_isolation.sql** | `manager_id` added to `employees`, `shift_configs`, `rosters` for multi-tenant manager isolation |
| **V4__historical_continuity.sql** | Historical continuity context support, audit tracking, unique constraints on `(roster_id, employee_id, assignment_date)` |

## 7. API Reference Summary

### Authentication & Profiles
- `POST /api/auth/login` — Authenticate user and issue JWT token
- `POST /api/auth/register` — Self-registration for Manager or Staff accounts
- `GET /api/auth/me` — Current authenticated user profile
- `GET /api/auth/managers` — List active managers for staff assignment

### Administration (Admin Only)
- `GET /api/admin/users` — List system user accounts with role and status filters
- `POST /api/admin/users` — Create user account with assigned role
- `PUT /api/admin/users/{id}` — Update user profile, department, manager, or status
- `DELETE /api/admin/users/{id}` — Remove user account
- `GET /api/admin/stats` — System user statistics
- `GET /api/departments` & `POST /api/departments` — Department management

### Shift Operations (Manager / Staff)
- `GET /api/rosters` — List rosters in manager's scope
- `GET /api/rosters/{id}` — Get roster details with all daily assignments
- `GET /api/rosters/by-month?month=&year=` — Retrieve roster by month/year
- `POST /api/rosters/generate` — Execute automated fairness roster generation
- `PUT /api/rosters/{id}/assignments` — Manual cell shift override
- `PUT /api/rosters/{id}/finalize` — Lock roster to FINALIZED state
- `GET /api/rosters/{id}/export` — Download formatted Excel XLSX matrix
- `DELETE /api/rosters/{id}` — Delete roster
- `GET /api/employees` — List manager's active employees
- `POST /api/employees/bulk` — Bulk add employee names
- `POST /api/employees/import` — Import employees from CSV/XLSX file
- `GET /api/shifts` — List manager's configured shift types and quotas

## 9. Key Conventions & Best Practices
- **Security & Authorization**: All operations endpoints require Bearer JWT authentication header and validate manager ownership.
- **Frontend Reactive State**: Standalone components with Angular Signals / RxJS subjects and inline scoped styles.
- **Mobile Touch Usability**: Maintain $\ge 44\text{px}$ – $48\text{px}$ touch targets and explicit `1rem` ($16\text{px}$) form control fonts.
- **Branding**: Sidebar footer reads "Created by DC".
